1 Signing key

The signing key is what makes a pass genuine. Create it once, keep the key file and its passphrase safe, and load it each time you open this page. Nobody can make a pass without it. A pass also needs the tool key (loaded below), so two things must be ready before you can issue a pass.

2 Issue a pass

The person starts the program and clicks Copy on the lock screen. That puts a PC request (a long line starting with PEBREQ1-) on their clipboard. They email it to you. Paste it here. The pass you make opens on that one computer only.

3 Register of passes

When connected to the shared Sheet (below), this list is the same on every PC and browser and is saved to the Sheet each time you issue or withdraw a pass. Without a connection it is kept only in this browser, so export a backup now and then.

Withdraw, Restore and Approve need the signing key to be unlocked (section 1). You can always look at the list. Every withdrawal is signed with the signing key, so a change made by hand in the Sheet is not trusted.

Shared register in Google Sheet not connected

Open the connect link on any PC or browser and Pass Maker connects to the Sheet by itself. Keep the link private: it contains the secret code. It is not sent to any website.

connection.json holds the Sheet address and secret code locked with your signing passphrase. Upload it to GitHub next to index.html. After that, unlocking the signing key on the online page also connects the Sheet, with nothing to paste. Use a long passphrase.

4 Online status (withdrawals and updates)

The program reads a small signed file, status.json, from the internet page. It lists the withdrawn passes (from the register above) and the newest program version. Make a new status.json whenever you withdraw or restore a pass, or have a new version. Upload it to the page, replacing the old one. When the Sheet is connected, the withdrawn list is read from it automatically. Without the Sheet, restore your register backup first so no withdrawn pass is missed.

Publish to GitHub automatically no token

With a GitHub token saved here, Withdraw and Restore sign a new status.json and publish it to your GitHub page by themselves. The token is a password for this one repository only (Contents: Read and write). It is kept in this browser, locked with your signing passphrase, and is never written into the page.
